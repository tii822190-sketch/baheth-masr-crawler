# إعداد الحسابات

## GitHub

المستودع مستقل وخاص. يحتاج Workflow إلى صلاحية قراءة المحتوى فقط، وهي مضمّنة في الملف. لا يحتاج الزاحف سرًا في النسخة التجريبية لأن SQLite تُنشأ داخل التشغيل وتُرفع كـartifact.

## Cloudflare حساب زميل الفريق

1. يضيف صاحب الحساب المستودع أو يفعّل التكامل مع GitHub.
2. ينشئ Worker منفصل عن Worker البحث الإنتاجي.
3. يضع `GITHUB_REPO=tii822190-sketch/baheth-masr-crawler` في `wrangler.toml`.
4. يضيف السر `GITHUB_TOKEN` بصلاحية Actions write على هذا المستودع فقط.
5. يضيف `CRAWLER_CONTROL_TOKEN` عشوائيًا طويلًا.
6. ينشر Worker من مجلد `worker`.

## قاعدة التجربة

نبدأ بـSQLite داخل GitHub Actions، لأنها تقلل الصلاحيات والمخاطر ولا تحتاج موصلًا خارجيًا. عند الحاجة إلى سجل دائم بين التشغيلات، ننشئ Turso staging منفصلة ونضيف أسرارها في GitHub فقط. Google Sheets يصلح للتقارير البشرية، لكنه ليس قاعدة مناسبة لتشغيل الزاحف بسبب البطء والتزامن والأنواع المحدودة.
