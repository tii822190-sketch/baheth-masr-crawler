# Baheth Masr Crawler

نظام محلي أولًا لاكتشاف صفحات المواقع وفهرستها. قاعدة التشغيل الوحيدة هي `db/crawler.sqlite` داخل المستودع. لا يعتمد المسار الأساسي على Turso أو Cloudflare أو قواعد بيانات خارجية.

## المكونات

يتكون النظام من ثلاثة جداول فقط:

| الجدول | الوظيفة |
| --- | --- |
| `sites` | المواقع التي يعالجها العنكبوت وحالة الاكتشاف ونقطة الاستكمال. |
| `site_pages` | طابور روابط الصفحات التي يعالجها الزاحف. |
| `index_results` | بيانات الفهرسة النهائية: الرابط والعنوان والوصف والأيقونة والكلمات المفتاحية والمقتطف. |

العنكبوت يختار موقعًا واحدًا بحالة `pending` في كل تشغيل. يقرأ روابطه من `robots.txt` وملفات Sitemap، يستبعد الروابط الإدارية والبحثية والملفات غير المناسبة، ويضيف بحد أقصى 10,000 رابط إلى `site_pages`. لا يتحقق من كل رابط عبر طلب منفصل؛ فحص الاستجابة مؤجل إلى الزاحف. الاستكمال التلقائي مغلق حاليًا، بينما تحفظ نقطة الاكتشاف الأخيرة في `sites.discovery_cursor` لأغراض التتبع.

الزاحف يقرأ حتى 500 رابط في التشغيل الواحد ويعالجها بعشرة عمال متوازية. عند اكتمال بيانات الصفحة ينقلها إلى `index_results` ويحذف صفها من `site_pages`. الصفحات التي تفشل تنتقل إلى `needs_review` لمحاولة أخيرة، ثم تحذف إذا بقيت تالفة. لا يضيف الزاحف أعمدة تشغيلية إلى جدول النتائج.

## الجدولة

يعمل Workflow **Discovery Spider** ثلاث مرات يوميًا عند `00:00` و`08:00` و`16:00` بتوقيت UTC. يعمل Workflow **Page Indexer** كل ساعة. كلاهما يستخدم قاعدة `db/crawler.sqlite` ويمنع التشغيل المتوازي على قاعدة البيانات نفسها.

يمكن تشغيل أي Workflow يدويًا من GitHub Actions. التشغيل اليدوي للعنكبوت يعالج موقعًا واحدًا فقط، والتشغيل اليدوي للزاحف يستخدم الإعدادات الافتراضية نفسها: 500 صفحة و10 عمال.

## التشغيل المحلي

```bash
npm ci
npm test
npm run db:init
npm run crawl:manual
```

تتغير الإعدادات عبر متغيرات البيئة، مثل `CRAWLER_BATCH_SIZE=500` و`CRAWLER_MAX_PAGES=500` و`CRAWLER_CONCURRENCY=10`.
