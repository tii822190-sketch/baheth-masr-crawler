# Baheth Masr Crawler

نظام محلي أولًا لاكتشاف صفحات المواقع وفهرستها. قاعدة التشغيل المحلية هي `db/crawler.sqlite` داخل المستودع، ثم تُنقل نتائج الفهرسة اليومية إلى جدولي `search_pages` و`search_pages_fts` في قاعدة Turso الخارجية.

## المكونات

يتكون النظام المحلي من ثلاثة جداول:

| الجدول | الوظيفة |
| --- | --- |
| `sites` | المواقع التي يعالجها العنكبوت وحالة الاكتشاف ونقطة الاستكمال. |
| `site_pages` | طابور روابط الصفحات التي يعالجها الزاحف. |
| `index_results` | بيانات الفهرسة النهائية: الرابط والعنوان والوصف والأيقونة والكلمات المفتاحية والمقتطف. |

العنكبوت يختار موقعًا واحدًا بحالة `pending` في كل تشغيل. يقرأ روابطه من `robots.txt` وملفات Sitemap، يستبعد الروابط الإدارية والبحثية والملفات غير المناسبة، ويضيف بحد أقصى 10,000 رابط إلى `site_pages`. لا يتحقق من كل رابط عبر طلب منفصل؛ فحص الاستجابة مؤجل إلى الزاحف.

الزاحف يقرأ الصفحات من `site_pages` ويعالجها بعمال متوازية. عند اكتمال بيانات الصفحة ينقلها إلى `index_results` ويحذف صفها من `site_pages`. الصفحات التي تفشل تنتقل إلى `needs_review` لمحاولة أخيرة، ثم تحذف إذا بقيت تالفة.

## المزامنة اليومية إلى Turso

يعمل Workflow **Sync Index Results to Turso** يوميًا عند `01:00 UTC`، ويمكن تشغيله يدويًا من GitHub Actions. ينفذ الخطوات التالية بالترتيب:

1. يقرأ جميع صفوف `index_results` من SQLite المحلية.
2. يتحقق من وجود جدولي `search_pages` و`search_pages_fts` في Turso ولا ينشئ أي جدول جديد.
3. يرسل الصفوف على دفعات باستخدام `upsert` اعتمادًا على الرابط `url` إلى `search_pages`، ثم يعيد إنشاء سجلها في `search_pages_fts`.
4. لا يحذف أي صف محلي أثناء النقل.
5. بعد اكتمال جميع عمليات الكتابة بنجاح، يحذف الصفوف المحلية داخل معاملة واحدة.
6. يتحقق من سلامة SQLite ومن أن الصفوف المنقولة فقط أزيلت محليًا.
7. يحفظ قاعدة SQLite المنظفة في Git.

حاليًا، ولأغراض الاختبار الأولي على Turso، يرسل Workflow بحد أقصى **30 صفًا لكل تشغيل** عبر `TURSO_MAX_ROWS=30`. بعد التأكد من نجاح التشغيل الحقيقي يمكن إزالة هذا الحد ليتم نقل جميع الصفوف المتراكمة.

إذا فشل الاتصال بـ Turso أو فشلت أي دفعة، يتوقف Workflow ولا يحذف البيانات المحلية، ويمكن إعادة تشغيله بأمان.

يحتاج المستودع إلى GitHub Secrets التالية:

| Secret | القيمة |
| --- | --- |
| `TURSO_DATABASE_URL` | رابط قاعدة Turso، مثل `libsql://...` |
| `TURSO_AUTH_TOKEN` | رمز الوصول إلى Turso |

## الجدولة

- **Sync Index Results:** يوميًا عند `01:00 UTC`.
- **Discovery Spider:** ثلاث مرات يوميًا عند `00:00` و`08:00` و`16:00 UTC`.
- **Page Indexer:** كل ساعة، باستثناء أوقات الاكتشاف ووقت مزامنة Turso عند `01:00 UTC`.

جميع العمليات تستخدم مجموعة GitHub Actions نفسها لمنع التشغيل المتوازي على قاعدة SQLite.

## التشغيل المحلي

```bash
npm ci
npm test
npm run db:init
npm run crawl:manual
```

لتشغيل المزامنة يدويًا محليًا، يجب توفير `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` كمتغيرات بيئة، ثم تشغيل:

```bash
node tools/sync-to-turso.mjs
```

تتغير إعدادات الزحف عبر متغيرات البيئة، مثل `CRAWLER_BATCH_SIZE=500` و`CRAWLER_MAX_PAGES=500` و`CRAWLER_CONCURRENCY=10`.

## قاعدة البيانات المحلية

قاعدة التشغيل الوحيدة محليًا هي `db/crawler.sqlite`. يجب أن تحتوي على الجداول التطبيقية الثلاثة: `sites` و`site_pages` و`index_results`. أما نسخة البحث طويلة الأجل فتوجد في جدولي `search_pages` و`search_pages_fts` داخل Turso بعد المزامنة اليومية.
